# ADR-0003: 파일은 줄 문자열과 줄별 색 배열, 레이어 배열로 적는다

- 상태: 채택 (Accepted)
- 날짜: 2026-09-28
- 대체: ADR-0001 §2 (칸 목록 JSON)

## 배경 (Context)

ADR-0001 §2 는 칠한 칸만 칸마다 객체 하나로 적었다(`{x, y, glyph, fg, bg}`). 파일은 짧지만 좌표 목록이라
열어 봐서는 그림을 알 수 없었다. 한 칸이 일곱 줄이라 104x19 판 하나가 수천 줄이 되기도 했다.

백로그에 레이어 기능이 있다. 레이어가 들어오면 형식이 다시 바뀌어야 하므로, 그 전에 레이어를 담을
틀을 먼저 둔다.

## 결정 (Decision)

아래는 뜻을 보이려고 줄을 모은 것이다. 실제 파일은 표준 들여쓰기라 색 배열의 칸마다 줄이 바뀐다(아래
"적는 꼴").

```json
{
	"size": {"width": 4, "height": 2},
	"layers": [
		{
			"glyphs": [
				"집 ┌",
				"<&  "
			],
			"fg": [
				[252,252,null,250],
				[null,null,null,null]
			],
			"bg": [
				[null,null,null,null],
				[17,null,null,null]
			]
		}
	]
}
```

- `glyphs` 는 줄마다 문자열 하나다. 판 폭만큼의 칸을 모두 채운다(빈 칸은 공백).
  - 넓은 글자는 문자열 안에서 두 칸을 먹는다. 오른쪽 반쪽(이어짐 칸)은 문자열에 없고 읽을 때 다시 세운다.
  - 읽을 때 grapheme 하나씩 떼어 x/ansi 로 잰 폭만큼 나아간다. 판이 칸을 놓는 셈(`Put`)과 같은 자다.
  - 여러 rune 으로 된 글자는 grapheme 으로 다시 나뉜다. 한 칸에 두 글자를 붙여 둔 것(`⇗▴`)은 읽으면
    두 칸이 된다. 보이는 모양은 같다.
- `fg` · `bg` 는 따로 둔다. 줄마다 판 폭 길이의 배열이고 x 가 곧 번호다.
  - 넓은 글자는 두 칸에 같은 색이 두 번 적힌다. 글자 수로 세면 줄마다 길이가 달라지고 x 로 찾을 수 없다.
  - 읽을 때 이어짐 칸의 색은 보지 않고 제 글자의 색을 따른다.
  - 터미널 기본색은 `null` 이다. 전 형식과 같다.
- `layers` 는 배열이지만 아직 하나만 쓰고 하나만 읽는다. 없거나 둘 이상이면 열지 않는다.
- 줄 수 · 줄 폭 · 색 배열 길이가 판 크기와 다르면 열지 않는다. 어디가 어긋났는지를 알린다.
- 적는 꼴은 표준에 맡긴다(`json.MarshalIndent`, 탭 들여쓰기). 처음에는 판의 한 줄이 파일의 한 줄이
  되도록 조각만 json 으로 적고 줄바꿈을 손으로 두었는데, 보는 사람이 들여쓰기를 신경 쓰지 말고 표준 메서드를
  쓰자고 해서 거두었다(2026-09-29). 대가로 색 배열은 칸마다 줄이 바뀌어 80x24 판이면 색만 4000 줄 가까이
  된다.
  그림은 `glyphs` 에서 줄마다 한 줄로 보인다. `< > &` 도 표준대로 `\u003c` 꼴로 적힌다. 읽을 때는 같다.
- 전 형식(칸 목록)은 읽지 않는다. v1.0.0 전에는 형식이 언제든 바뀔 수 있다는 ADR-0001 §2 의 전제를
  따른다. 버전 필드도 여전히 두지 않는다.

## 결과 (Consequences)

- 파일을 열면 `glyphs` 에서 그림이 그대로 보인다. 사람도 Claude 도 줄과 열로 읽는다.
- 빈 칸도 모두 적으므로 빈 판이 큰 만큼 파일이 커진다. 칸마다 색 둘이 `null` 로라도 적힌다.
- redzone 의 `docs/mock/` 파일은 전 형식이라 paint 로 열리지 않는다. redzone 의 sketch 로는 그대로 열린다.
- 레이어 기능이 들어오면 빈 칸과 투명 칸을 가를 표현이 더 필요하다. 지금은 공백 · `null` 이 곧 빈 칸이다.
